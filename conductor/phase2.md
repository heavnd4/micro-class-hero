# 视频知识自动化生产系统 - 阶段 2：交付优化与易用性 开发方案

## 1. 目标
在巩固了批量处理底座的基础上，第二阶段的重点是**丰富最终交付物**（增加 SRT 字幕）以及**极大降低使用门槛**（开发图形化界面 GUI）。

## 2. 核心功能设计

### 2.1 同步生成 SRT 字幕文件
*   **功能背景**：原脚本在“转录”步骤（第一步）仅输出了纯文本 `01_transcript.txt`。但 `faster-whisper` 实际上在识别时附带了极其精确的时间戳（`start` 和 `end`）。
*   **实现方案**：
    *   修改 `step1_transcribe` 函数。
    *   在遍历 `segments` 时，不仅提取 `seg.text`，还要提取 `seg.start` 和 `seg.end`。
    *   编写一个格式化函数，将秒数（如 `61.5`）转换为标准 SRT 时间码格式（如 `00:01:01,500`）。
    *   除了生成 `01_transcript.txt` 外，同步生成 `01_transcript.srt` 或直接将最终字幕保存为 `[视频名]_字幕.srt` 到输出目录，与 Word 教材和考题并列。
*   **输出示例**：
    ```text
    1
    00:00:01,000 --> 00:00:04,500
    大家好，我是老K
    
    2
    00:00:04,500 --> 00:00:08,200
    今天我准备讲厨房的水电专题
    ```

### 2.2 开发可视化操作界面 (GUI)
*   **技术选型**：推荐使用 Python 内置的 **Tkinter** 库配合 **ttkbootstrap**（美化主题），或者使用 **Gooey** 库。考虑到打包成独立 `.exe` 的体积和系统兼容性，**Tkinter** 是最稳妥的选择，不需要额外安装庞大的依赖。
*   **界面布局设计**：
    *   **标题区**：软件名称与简介。
    *   **路径配置区**：
        *   “视频输入目录”选择框（提供 [浏览...] 按钮）。
        *   “结果输出目录”选择框（提供 [浏览...] 按钮）。
    *   **参数配置区**：
        *   API Key 输入框（密码类型，支持保存历史记录）。
        *   截图频率设置（如下拉框选择：30秒/60秒/120秒）。
    *   **控制与日志区**：
        *   一个醒目的 [开始处理] 按钮。
        *   一个只读的多行文本框（用于实时滚动显示后台打印的进度日志 `print` 信息）。
*   **架构改造逻辑**：
    *   将现有的 `main()` 函数封装为一个可以接收参数（`video_dir`, `out_dir`, `api_key`, `frame_every`）的工作线程任务。
    *   启动 GUI 主循环，当用户点击“开始”时，开启一个后台守护线程（Thread）执行视频处理逻辑，通过队列（Queue）或事件回调将 `print` 信息实时重定向到 GUI 的日志文本框中。这能保证处理视频时界面不会“卡死无响应”。

## 3. 实施步骤规划

### 步骤一：SRT 算法与状态补全
1.  编写时间戳格式化工具函数 `format_timestamp(seconds)`。
2.  修改 `step1_transcribe`，在转录循环中同时生成并写入 SRT 格式文本。
3.  测试单个视频，验证播放器能否正常挂载字幕并对齐时间。

### 步骤二：GUI 骨架搭建
1.  引入 `tkinter` 编写主窗口、输入框和按钮。
2.  实现文件浏览对话框逻辑（选择文件夹）。
3.  利用 `json` 配置文件或简单的 `.ini` 保存用户的 API Key 和常用目录，实现“记住上次配置”的功能，免去每次填写的麻烦。

### 步骤三：异步桥接与日志重定向
1.  重写 `print` 函数或自定义日志记录器（Logger），使其不仅输出到控制台，也更新到 GUI界面的 Text 控件中。
2.  利用 `threading.Thread` 将耗时的 `process_single_video` 放入后台执行。
3.  添加异常捕获，若 API 报错或内存不足，通过弹出对话框 `MessageBox` 提示用户。

## 4. 交付预期
完成本阶段后，您将获得一个带有界面的应用程序。您只需双击运行，在图形界面上点选视频所在的文件夹，点击“开始”，即可端起咖啡等待程序自动输出 **教材 Word + 考题 Word + SRT 字幕** 三件套。

## 5. GUI 细节体验优化 (2026-04-24 增补)
**需求背景**：用户在 GUI 中填写阿里百炼 API Key 时，虽然已实现持久化记忆，但星号掩码导致无法核对当前记忆的 Key 是否正确。
**实施方案**：
1. **保留掩码默认状态**：输入框默认配置 `show="*"`，保护隐私。
2. **增加可视切换组件**：在 API Key 输入框右侧增设一个“眼睛”图标按钮 (👁)。
3. **交互逻辑**：点击该按钮时，若当前为掩码状态则切换为明文显示，若为明文则恢复为星号掩码。为防止控件挤压错位，输入框与按钮将被包装在一个独立的 `tk.Frame` 中并列排布。

## 6. 截图频率智能化模式选择 (2026-04-24 增补)
**需求背景**：随着核心脚本引入基于 OCR 的“智能截图”（自动识别 PPT 翻页），原有的“截图频率（秒/张）”输入变得多余，甚至可能对用户产生误导。为了兼顾非技术用户的易用性以及对复杂场景的兼容性，采用“模式切换”方案。
**实施方案**：
1. **GUI 界面改造**：
    *   在“截图频率”上方增加一行“截图模式”。
    *   提供两个单选按钮 (Radiobutton)：**智能识别 (推荐)** 和 **固定频率**。默认选中“智能识别”。
    *   **联动逻辑**：当选择“智能识别”时，将下方的“截图频率”输入框置灰禁用 (`state="disabled"`)；当选择“固定频率”时，恢复可用状态 (`state="normal"`)。
2. **持久化与透传**：
    *   `gui_config.json` 中新增 `extract_mode` 字段记录用户的模式偏好。
    *   `worker_thread` 启动时，将该模式通过全局变量 (如 `v2w.EXTRACT_MODE`) 透传给核心脚本。
3. **核心脚本适配 (`video_to_word.py`)**：
    *   在 `step2_extract_frames` 开头增加逻辑判断：若当前为“固定频率”模式，则直接跳过 FFmpeg 场景检测和 PaddleOCR 识别流程，执行原有的按固定频率截图逻辑；若为“智能识别”，则执行基于 OCR 的去重流程。
